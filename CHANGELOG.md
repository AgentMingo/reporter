# Changelog

Each version is the `VERSION` constant in `reporter.mjs`. Reporters update themselves to the version agentmingo.com serves, unless their person turned that off.

From version 11 on, each entry gives the SHA-256 of `reporter.mjs` as agentmingo.com served it, and the date it started serving it. This repository starts at version 12; each release is published here by hand for now. Versions 1 to 11 came before this repository and their files aren't published here. The entries for 1 to 10 are summaries of what changed, from the script's history in AgentMingo's own repository, and their dates are when each version was written, not when it was served.

## 23 (served from 2026-11-03)

SHA-256 of `reporter.mjs`: `57662f9c1d3640e052d0de5bd6d5fc84069546f15133c4eb5d5bcac4b3a68c48`

- Long prompts were priced at base rates. A model's provider can bill a request whose prompt is over a threshold at higher, long-context rates (Haiku 5.5: over 100,000 tokens). Before 23, the reporter added every request's tokens to the same five fields for its model (`input`, `output`, `cacheRead`, `cacheWrite5m`, `cacheWrite1h`), so AgentMingo couldn't tell those requests apart and priced all of them at the model's base rates.
- What it classifies, and how (`takeUsage()`). Each response in the transcript, counted once by its id as before, is one request. Its prompt is its input tokens, cache reads and cache writes together (`input_tokens`, `cache_read_input_tokens`, and the 5-minute and 1-hour writes in `cache_creation`, or `cache_creation_input_tokens` when the transcript doesn't split them); its output tokens don't count toward it. When the prompt is over the model's threshold (`LONG_CONTEXT_THRESHOLDS`: only `claude-haiku-5-5`, 100,000), all of that request's tokens, its output included, are counted in the long-context fields instead of the base ones. A prompt of exactly 100,000 stays in the base fields. Every other model has no threshold, and its counts are as in 22.
- Which model ids match (`longContextThreshold()`). The id is trimmed and lowercased, and a trailing tag in brackets (letters and digits, such as `[1m]`) is dropped. It then matches an entry exactly, or that entry followed by a date (`-20260901` or `-2026-09-01`), `-latest` or `-0`. So `claude-haiku-5-5-20260901`, `claude-haiku-5-5-latest` and `claude-haiku-5-5[1m]` use Haiku 5.5's threshold, and an id that matches no entry this way has none. Counts are still kept and sent under the id as the transcript gives it.
- What it sends that's new: in `usage`, a model's entry can carry five more fields, `longInput`, `longOutput`, `longCacheRead`, `longCacheWrite5m` and `longCacheWrite1h`, cumulative from when the reporter first saw the session, like the base ones. They're there only once one of that model's requests was long, and left out otherwise. Tokens a thread counted before its computer updated to 23 stay in the base fields. Nothing else.
- The header's list of what it sends now says token counts are split into base and long-context buckets per request when the model has a long-context pricing tier, and that a request whose prompt is over the threshold is counted in the long bucket.
- Changes that don't change what it does: `takeUsage()` works out a request's counts before adding them (a request that isn't long adds the same as in 22), and `LONG_CONTEXT_THRESHOLDS` and `longContextThreshold()` are exported (AgentMingo's tests check the table against its prices).
- Everything else in version 22 is unchanged.
- On AgentMingo's side, not in this file: AgentMingo takes the five fields (whole numbers, 0 when left out, like the base ones), prices them at the model's long-context rates in its price table, and counts them in a thread's token totals with the base ones. Tokens in the base fields, and everything older reporters send (base fields only), stay at base rates. An organization that sets its own prices for a model keeps AgentMingo's long-context rates for it: the organization's settings page shows its long-context input and output rates, which can't be edited there. AgentMingo's Privacy Policy says the token counts are split this way.

- Where it looks, stopping at the first place that has a clone. First the folders Claude Code has opened: the keys of `projects` in its state file, picked as `claudeStateFile()` picks it, only read and without Claude Code's lock, the most recent `lastStartTime` first, then in the file's order.
